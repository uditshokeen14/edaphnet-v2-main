EdaphNet v2: Every File Explained

What each file is, what it uses, and what it feeds into · 3 October 2026 · repository github.com/Sudeep-Sharma1/edaphnet-v2
How to read this. Section 1 shows the whole project as one chain, from raw data to the paper. Section 2 traces one number from the paper back to the code, so you can see how the files connect. Sections 3 onwards go folder by folder. Each file has a coloured tag: Paper used for the paper's results · Record notes what was decided or found · Demo for showing the project · App the separate farmer app, not in the paper · Future for paper 2 (real photos) · Tool helper.

1. The whole project in one chain

Everything in the paper is produced by this chain. Each step reads the output of the step before it.

1 Datadownload_ossl.py gets 3 OSSL files into data/raw/
2 Clean datasetsbuild_ossl_dataset.py makes data/processed/t1_*.npz and splits
3 Witnessfit_witness_ladder.py makes colour/spectrum predictions witness_*.npz
4 Experimentsconfigs/*.yaml + run_real.py use the method in src/edaphnet2/
5 Resultsrun folders in results/runs/; analysis scripts write results/exploratory/
6 Writingdocs 11–26, figures, docs/paper/draft_v0.md, PDFs in reports/
1 → 2 → 3 → 4 → 5 → 6 (read left to right, top row then bottom row)

Three side branches use pieces of the chain but do not feed the paper:

  • Demos: train_colour_brain.py builds a colour model in models/, and serve_demo.py uses it with the method to run demo_site/live.html. build_demo_page.py builds the offline page demo_site/index.html from the run records.
  • Future (paper 2): phone.py + process_photos.py turn real soil photos into witness values, following the protocol in doc 15 and the sheets in templates/.
  • App: everything under app/ plus the app_*.py scripts and data/app_raw/.

2. Follow one number from the paper to the code

Example: the paper says "with a spectrometer, EdaphNet found +0.092 more errors than the best existing method".

  1. Paper: docs/paper/draft_v0.md §7.4, table row "Spectrometer".
  2. Document that reports it: docs/21_kssl_preregistered_results.md, the pre-registered verdict.
  3. Rules it was judged by: docs/18_preregistered_amendment_v2.md, written before the test.
  4. Script that computed the verdict: scripts/analyse_amendment.py.
  5. Run folder it read: results/runs/20261001-234902_real_kssl3_095deaa/ (amendment_A1.csv, metrics_by_setting.csv).
  6. Settings used: configs/real_kssl3.yaml (copied into the run folder as config.json).
  7. Program that ran it: scripts/run_real.py, which calls the method in src/edaphnet2/inference.py and the baselines in src/edaphnet2/baselines.py.
  8. Data it used: data/processed/t1_kssl3.npz and witness_kssl3.npz, built from data/raw/ossl/.
  9. Proof of the code version: provenance.json in the run folder (commit 095deaa).

Every other result works the same way. REPRODUCE.md lists the command behind each one.

4. src/edaphnet2/: the method (the heart of the project)

This is the research code. It was frozen at commit 095deaa before the pre-registered test, so the test could not be tuned afterwards.

FileWhat it doesUses → / used by
inference.py PaperThe method. Looks at a whole batch of 24 reports at once, tries every likely swap and every error type, and gives each report a suspicion score, a most likely explanation and a suggested correction.uses operators, swaps, witness, space · used by run_real.py, run_sim.py, demos
operators.py PaperThe list of value errors: ×10, ÷10, unit mix-up, swapped digits, swapped columns, gross error. Also plants random errors for testing.used by inference, simulate, run_real
swaps.py PaperThe swap patterns: neighbours swapped, a whole tray shifted by one or two places, any two samples swapped.used by inference
witness.py PaperWitness models: from colour or spectrum, predict each sample's carbon, nitrogen etc. with an uncertainty.used by inference, fit_witness_ladder, serve_demo
baselines.py PaperThe 7 competitors B0–B7 (range checks, soil rules, lab-only model, witness interval, swap matcher, supervised classifier, cleanlab) and B6 rule-based repair.used by run_real, run_sim
conformal.py PaperFalse-alarm control: turns scores into p-values using clean calibration reports, then Benjamini–Hochberg.used by run_real, rescore_pools
metrics.py PaperHow results are measured: errors found when re-testing the top 5%, power, false-alarm rate, per pool of 50 batches.used by run_real, run_sim
space.py PaperHow each property is stored and printed (decimal places, log scale), so planted errors look like real printed reports.used by almost every module
real_data.py PaperLoads the soil data; defines the property sets (ICRAF 8, KSSL 3); computes soil colour from a spectrum.used by build_ossl_dataset, run_real
properties.py, simulate.py PaperMake the synthetic soils, batches and errors for the first test (simulation).used by run_sim
tracking.py PaperWrites the run record: settings, code version, computer, timing. This is what makes every number traceable.used by every experiment
phone.py Future DemoReal-photo processing: colour-card correction, true soil colour, blur and exposure checks, texture.used by process_photos, serve_demo

10. Words you will see

WordMeaning
WitnessA cheap, independent look at the same soil sample (its colour, or a spectrum) that the lab cannot corrupt.
SwapA report that belongs to a different sample (labels or tray positions mixed up).
Value errorOne wrong number in a report (×10 slip, unit mix-up, swapped digits, gross error).
Batch / poolA batch is 24 reports (one lab tray); a pool is 50 batches (about one lab-day).
Re-test budgetThe share of reports the lab can afford to re-test; we use the top 5% most suspicious.
Baseline (B0–B7)An existing or simple method we compare against; B5 (supervised) was usually the strongest.
Pre-registrationWriting the pass/fail rules down and committing them before running the test.
ExploratoryAn analysis done after seeing results; useful for ideas, not proof.
FDR / false alarmsThe share of flagged reports that were actually fine; we aim for 10%.
CalibrationClean reports used to decide how unusual a score is; reusing the same samples was our mistake.
Run folder / provenanceThe saved record of one experiment, including the exact code version.
